# 多路复用与显示调度（display-multiplexer-notes）

> `SKILL.md` §4.6、§2.4.3 的完整版：PCA9548A 选通字节与 STOP 生效语义、三块同址屏的调度分层、驱动接口设计。删掉本文件，主流程仍可执行，但会失去选通细节与调度依据。

## 一、PCA9548A 是什么

8 通道双向 I2C/SMBus 开关 1-of-8，解决**同址器件冲突**：三块 SSD1306 都是 0x3C，挂同一条总线会同时应答，无法区分。给每块屏一条独立通道，地址冲突就在通道层面被隔离——**不需要动烙铁改地址**。

| 项 | 值 |
|---|---|
| 7 位地址 | 1110 A2 A1 A0；全接地 = **0x70**，一条总线最多 8 片 0x70–0x77 |
| 供电 | 1.65–5.5V（85–125°C 时降至 1.65–3.6V） |
| I/O | 5V tolerant（本方案全 3.3V 用不到） |
| 频率上限 | 400kHz |
| RON | 典型 5Ω，最大 12Ω |
| RESET | active-low（pin24），下游总线卡死时的恢复手段 |
| 内部上拉 | **无**，每条被选通的下游通道需各自外部上拉 |
| 热插拔 | 支持 |

地址跳线表：LLL=0x70、LLH=0x71、LHL=0x72、LHH=0x73、HLL=0x74、HLH=0x75、HHL=0x76、HHH=0x77。

**上电默认所有通道断开**——复位与上电后必须软件显式选通才通。此时下游三块屏全部不可见，**扫不到 0x3C 是正常的，不是屏坏了**。

## 二、控制寄存器三条决定代码的细节

来自 TI 数据手册 SCPS207H §7.5.4：

**① 选通字节 = `1 << N`。**

```text
ch0 = 0x01   ch1 = 0x02   ch2 = 0x04   ch3 = 0x08
写 0x00 = 全部断开
```

**② 通道在 STOP 条件之后才真正生效。**

> "When a channel is selected, the channel becomes active after a stop condition has been placed on the I2C bus."

目的是保证切换瞬间所有 `SCn`/`SDn` 都处高电平，不产生假起始/假停止。**代码含义：选通必须是一次完整的 `beginTransmission()` → `write()` → `endTransmission()`**，不能只 `write()` 不收尾，也不能指望写在半途就切过去。

**③ 多字节只保留最后一个。**

> "If multiple bytes are received by the TCA9548A, it saves the last byte received."

连续写两个字节不叠加，后一个覆盖前一个。

**上电后第一件事必须是显式选通某一路（或确认全断）。**

## 三、上拉归属与并联风险

- **上游（ESP32 ↔ PCA9548A）**：成品模块板载 10k，不需再加；
- **下游（PCA9548A ↔ 屏）**：SSD1306 模块板载上拉，不需再加；
- **禁止**：再往 SDA/SCL 补 4.7k。重复并联把等效阻值拉得过低，逼近 SSD1306 低电平驱动极限（标称 sink ≈ 3mA）。

`link-probe` 实测只证明**屏那一侧**有上拉，不能证明 PCA9548A 上游有上拉——两件事互相独立。

**并联风险量化**：

| 配置 | 等效上拉 | 判断 |
|---|---|---|
| 三块屏各 4.7k 仅屏上拉 | ≈1.57k | 尚可但已偏低 |
| 三块屏 4.7k + 模块八路各挂 10k | < 1k | 逼近 sink 极限 |

**故采用「一次只选通一路」**：选通道 → 刷屏 → 断开 → 下一路。任一时刻只有一块屏的上拉在线，既不存在并联，又能故障隔离、逐通道观测应答。这是设计约束，不是优化。

## 四、驱动接口设计

```cpp
bool pca9548a_select(uint8_t channel);        // 0–7，只选通这一路其余全断
bool pca9548a_deselect_all();
bool Display::begin(uint8_t channel);         // 每块屏绑定一个通道
void Display::flush();                        // flush 前自动选通用完断开
```

**通道缓存**：驱动内部记住当前选通通道，`select(n)` 若 `n == 当前通道` 直接返回、不产生 I2C 事务。上层可放心在每个绘制调用前都写一次 `select()`，不浪费总线。

**刻意不暴露 `pca9548a_write_mask(uint8_t mask)`**——避免调用方同时选通多路触发上拉并联。接口层面就把风险关掉。

## 五、三块屏必须实现的保护

源自从机离线拖垮节拍的实测教训（一块屏放大三倍）：

1. **每通道独立探测**——启动时逐通道探测，记录哪些屏在线；
2. **离线即跳过**——某通道屏不在线，该通道 `flush()` 立即返回，不做任何 I2C 事务；
3. **节拍解耦**——游戏 tick 用 `millis()`，与屏幕在线状态完全解耦。即使三块屏全掉线，游戏逻辑仍以精确 1Hz 推进。

## 六、刷新调度按变化频率分层

| 屏 | 角色 | 变化频率 | 优先级 |
|---|---|---|---|
| 屏 3 | 日志 | 事件驱动，瞬时 | 最高 |
| 屏 2 | 数值 | 2–5Hz 定时 | 中 |
| 屏 1 | 角色 | 1–2Hz，仅状态变化 | 最低 |

**轮询顺序：日志 → 数值 → 角色；每轮最多刷一块屏**（有实际变化的那块），避免三屏同时刷把总线占满。

**理由**：养成游戏的信息有时间维度——角色图变化最慢（看表情就知道状态）、数值变化中等（要看到条在涨）、日志变化瞬时（要看到刚发生了什么）。按变化频率分层天然形成调度优先级。

## 七、接线与通道分配

上游接线（建议值，待 bringup 确认）：SDA → GPIO8、SCL → GPIO9、VCC → 3V3、A0/A1/A2 → GND（目标 0x70，**以实际扫描结果为准**）、RESET → 3V3 或悬空。A0=pin22、A1=pin23、A2=pin18。

通道分配：**ch0 角色屏、ch1 数值屏、ch2 日志屏**，ch3–7 预留。三块屏全保持 0x3C 出厂地址。

## 八、bringup 必做清单

1. 扫 0x70–0x77 确认实际地址（成品模块跳线可能焊死，不一定遵守「全接地 = 0x70」）；
2. 万用表量各通道 SDA/SCL 对 VCC 阻值，确认模块上拉挂上游还是八路全挂（决定是否触发并联风险）；
3. 逐通道探测 0x3C；
4. **三块屏显示不同内容**——同内容无法区分是否真的切换成功；
5. 记录 `endTransmission()` 是否返回 5。

**验收标准：三块屏显示三个不同的字符串，且任意时刻单独刷新其中一块不干扰另外两块。**

## 九、为什么 bringup 必须先于上层代码

硬件风险与软件风险的**验证成本差异极大**：硬件问题只能靠实物验证，且拓扑假设一旦错误（如 PCA9548A 实际地址不是 0x70，或键盘实为 I2C 编码型改变了拓扑），受影响的是整个上层架构。因此 bringup 是 M1 及之后所有里程碑的阻塞前置——越早发现越便宜，且 bringup 产出的驱动、通道探测逻辑、诊断输出全部是后续项目的直接依赖，不是一次性丢弃的代码。
