# 脚本用法（scripts）

> 本文件是 `scripts/` 下三个脚本的说明。它们是 Python 3 **纯标准库**单文件（无第三方依赖），kebab-case 命名。
> 调用方式不在本文件里重复——先读本文件知道「这个脚本解决什么问题、什么时候用」，具体参数看脚本顶部的 docstring。

---

## 一、`html-to-markdown.py` —— 抓文档页转 Markdown

**解决什么**：把文档站的渲染页抓成 Markdown，同时把正文图片下载到本地并改写引用。

**什么时候用**：需要把厂商文档站存档成 Markdown 时。第三方框架的在线文档站（Sphinx/Docusaurus/VitePress 之类）都适用。

**配置外置**：脚本本身不含任何站点或产品常量，站点与页面清单写在一个 JSON 配置里：

```json
{
  "base_url": "https://docs.example.com",
  "output_dir": "../.doc/MyBoard",
  "asset_dir": "assets",
  "article_marker": "<div class=\"theme-doc-markdown markdown\">",
  "pages": [
    {"slug": "MyBoard", "filename": "01-产品总览.md"},
    {"slug": "MyBoard/Resources", "filename": "02-相关资料.md"}
  ]
}
```

**几个字段的用法**：

- `article_marker` —— 文章正文容器的起始标记。渲染页的正文**未必**是 `<article>`，常见的是某个带 class 的 `<div>`。留空则脚本回退去找 `<article>`，找不到就报错退出（不会静默抓出整个页面）。
- `asset_dir` —— 图片落地目录名，默认 `assets`。
- `output_dir` —— 相对脚本当前工作目录解析。
- `source_label` / `collect_method` / `collect_time` —— 写进文件头部的来源标注。默认 `官方来源` / `文档站渲染页 → Markdown` / 当天日期。

**生成的文件头**固定四行：标题、来源 URL、采集时间与方式、「本页为原文存档」的声明。整理文档的文件头格式不同（带出处标记说明），见 [`archive-layout.md`](archive-layout.md)。

**已知要处理的六类渲染问题**（脚本已处理）：

| 问题 | 表现 | 处置 |
|---|---|---|
| HTML5 可选结束标签 | `<td>`/`<th>`/`<tr>`/`<p>`/`<li>` 不闭合 → 整页塌成一坨连续文字 | 解析器自己补全结束标签（`close_cell` / `emit_row` / `close_p`） |
| 提示块内容丢失 | 警告框只剩标题，正文被吞 | 提示块单独缓冲，闭合时整块渲染成引用块 |
| 嵌套列表 | 重复渲染成多段 | 列表渲染时跳过子列表的统一处理 |
| `data:` URI 内联图标 | 落成无效引用 | 替换为文字占位 |
| 表格 | 丢列或丢表头 | 表格转 Markdown 表格，首行自动生成表头分隔 |
| 代码块 | 反引号不配对 | 代码块内不处理内联标记，原样输出 |

**关于 HTML5 可选结束标签**——这是最容易踩的一个。浏览器会自动补 `<p>` `<li>` `<td>` `<tr>` 的结束标签，`html.parser` 不会。后果是：

- 表格的每一行会连成一段没有换行的文字；
- 段落的边界全部错位，后一段会被并进前一段；
- 提示块里的正文被当成标题吞掉。

**必须自己补**。脚本里的 `close_cell()` / `emit_row()` / `close_p()` 就是干这个的，不要图省事删掉。

**关于提示块**——`theme-admonition` 这类结构有独立的标题 div 与内容 div。标题 div 闭合后要把「正在收标题」这个状态清掉，否则后续正文会被当成标题继续吞。用 `heading_depth` 记录标题 div 的嵌套深度，闭合时比较深度即可。

**节制**：只发 GET、只抓公开页面、请求之间留间隔（默认 1 秒）。镜像大仓库时这不是主要开销，但抓几百个页面时它就是。

**局限**：只处理服务端渲染出的 HTML。页面若是客户端渲染（正文在 JS 里），抓到的是空壳——先在浏览器里确认正文在初始 HTML 里。

## 二、`check-links.py` —— 检查归档的内部链接自洽

**解决什么**：三类检查——**缺失引用**（md 里写的相对路径在磁盘上不存在）、**未引用资源**（资源目录里的文件没被任何 md 引用）、**外链清单**（只统计，不联网）。

**什么时候用**：每次改完归档的 md 之后，交付之前。

**默认只查顶层 `.md`**。归档里通常还镜像了上游源码树（`reference-source/`），那些第三方 README 里的相对链接指向上游仓库内部路径，在本地并不成立——一并检查会产生大量误报，淹没真问题。要连嵌套目录一起查，显式开 `--recursive`。

**退出码**：0 = 无缺失；1 = 有缺失引用；2 = 参数或目录错误。可直接用在 CI 或钩子里。

## 三、`snapshot-diff.py` —— 目录树逐文件 sha1 对账

**解决什么**：把两个目录树逐文件算 sha1，输出四类结果：

- **上游有、本地无** —— 上游新增；
- **本地有、上游无** —— 上游删除；
- **两边都有但 sha1 不同** —— 上游改了内容；
- **两边都有且 sha1 相同** —— 确认无变化。

**什么时候用**：官方更新后对账；以及**镜像落地后的完整性校验**（此时期望结果是「全部相同」，用来证明镜像确实是逐字节副本）。

**为什么必须逐文件 sha1**：官方把一个目录整体改名但代码一个字节没动时，按目录看是大改，按文件看是 255 个文件里 253 个没变。这种事只有 sha1 对账能识破。

**开销**：全量算 sha1 与文件总量成正比。几百 MB 的仓库在机械盘上要几分钟——正常，不要因此改用「抽样比对」这种看起来省事实际漏东西的做法。

## 通用纪律

- **脚本里不许出现本机绝对路径**。参数化，缺省值用相对路径。技能要公开分发，脚本里一个 `C:\Users\<用户名>\...` 就等于把使用者的身份信息公开了。
- **中文文本用 UTF-8 无 BOM、LF 写回**。不要用 PowerShell 的默认编码处理。
- **脚本不写死站点与产品常量**。要改目标就改配置，不改代码。
- **只读脚本优先**。会写文件的脚本在完成后报告里说清写了什么。
