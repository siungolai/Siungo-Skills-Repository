# commit-auto 作为 commit-report 之前的节奏层

commit-report v1.1 已经沉淀了风格匹配、两区审阅模板、推送降级脚本（`scripts/push-via-api.py`）、SHA 三重校验与完整安全边界，并经过实战修订。因此 commit-auto 只新增「何时提交、如何切分」这一层，实际提交动作仍经 commit-report 的审阅门执行；commit-auto 向审阅门传递的是**提交意图**，而不是最终 commit message。

这条边界的接缝有两处。其一，**message 一律由审阅门按其既有风格规则生成**，commit-auto 只交付「范围（文件清单）+ 提交意图（一句话）」——理由是风格匹配规则在 commit-report 里已经过实战打磨，两边各留一份必然漂移。其二，**执行方式为读盘复用**：commit-auto 不「调用」commit-report 这个技能，而是读取其 `SKILL.md` 并按其 §2–§3 执行分析与审阅内容生成。理由有二：一是规则仍只有那一份文件作为事实源，运行时读取即可，不需要复制文本；二是 commit-report 的流程硬性要求逐笔等待用户确认，直接调用会把「等待」带进自动节奏，而读盘复用只借用它的分析与文案规则，确认由会话级授权覆盖（见 ADR-0002）。

替代方案是让 commit-auto 取代 commit-report 成为唯一提交入口。被否决的理由：那要求把已验证的降级通道与安全边界整体重写一遍，风险高于收益，且两个技能会在仓库里并存并互相漂移。
