# commit-report：审阅门式 Git 提交

定位：与内置 /commit 命令互补——本技能以**强制审阅门**为核心，用户看到变更总揽与 commit 信息全文并明确确认后，才执行提交。**push 默认不执行**，仅在用户明确选择时进行。

## 一、前置自检（任一不满足即终止并报告）

1. 当前目录必须是 git 仓库；不是则报错退出。
2. 空仓库（无任何提交历史）：跳过"匹配既有风格"，按通用规范生成首次提交信息，并在审阅中注明"首次提交，无历史风格可匹配"。
3. 无任何变更（工作区与暂存区均干净且无未跟踪文件）：报告"无事可提交"，结束，不进入审阅。
4. detached HEAD 状态：提示先切换或新建分支，不执行任何操作。

## 二、分析阶段

1. **仓库状态**：读取当前分支名、与上游的领先/落后关系。
2. **风格匹配**：读取最近 10 条提交的主题行，归纳既有风格——前缀习惯（如 `feat:` / `fix:` / `docs:` 或无前缀叙述）、语言（中英）、时态与标点；无明确风格可循时，默认 conventional commits、简体中文。
3. **变更盘点**：按三组分类——已暂存 / 未暂存 / 未跟踪。
4. **改动摘要**：每文件一行（变更类型＋核心内容），规则：
   - 单文件 diff 超过 300 行：只读头部与 `diff --stat`，标注"大改动（概要）"；
   - 二进制文件：标注"二进制文件（大小 X）"；
   - 未跟踪新文件：读文件头部判断性质后写摘要。
5. **敏感文件预警**：文件名匹配 `.env`、`*.key`、`*.pem`、`credentials`、`secret`、`id_rsa` 等模式时，在审阅中**加粗警示"疑似敏感文件"**；不阻断，由用户在审阅中决定是否剔除。

## 三、审阅展示（固定模板，缺项注明"无"）

1. **仓库与分支**：分支名、与上游关系；
2. **commit 信息全文**：主题行＋正文，风格与既有提交一致；
3. **变更总揽表**（三组分组）：

   | 状态 | 文件 | 改动摘要 |
   |---|---|---|

4. **敏感文件预警**（如有）；
5. **回应路径**（固定文案）：

```
请回复：
① 确认提交（仅 commit，不 push）
② 确认提交并 push（推送至当前分支上游）
③ 需要调整（改 commit 文案 / 剔除文件 / 其他）
```

## 四、回应判定与执行

- **回复①或明确肯定词**（确认／同意／OK／可以／提交吧等）→ 按确认范围执行 `git add`（默认全量变更；用户点名剔除的文件排除在外）→ `git commit`（HEREDOC 格式书写提交信息）。
- **回复②** → 同上执行 commit，随后 push 至当前分支上游；当前分支无上游时，先追加确认是否执行 `git push -u origin <分支名>`，确认后才执行。
- **回复③** → 按反馈修订（commit 文案或提交范围），重新完整展示审阅；修订循环次数不限，由用户主导。
- **用户发起时明说"跳过审阅直接提交"** → 不展示直接执行（当次显式指令优先），但第五节安全边界仍然全部适用。

## 五、安全边界（硬性，任何路径下均适用）

1. 禁用 `--no-verify`；pre-commit 钩子失败时报告原因并停止，不绕过。
2. 禁止 force push；禁止 amend 已推送的提交。
3. push 被远端拒绝（non-fast-forward）或网络失败：只报告差异与建议（如先 pull），不自动 pull／rebase／重试。
4. 不擅自新增或删除文件，不改动用户未确认范围之外的内容。
5. commit 信息语言跟随仓库既有风格；无历史可参考时使用简体中文。
