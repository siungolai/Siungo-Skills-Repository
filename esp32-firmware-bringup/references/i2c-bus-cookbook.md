# I2C 总线手册（i2c-bus-cookbook）

> `SKILL.md` §3、§4.3、§5.4 的完整版：总线层面的规则、上拉归属、事务分块、电平转换选型，以及本机三个真实案例（GPIO1/2 不通、从机离线拖垮节拍、1602 背包假象）。删掉本文件，主流程仍可执行，但会失去判据依据。

## 一、错误码判读

`Wire.endTransmission()` 的返回值直接决定下一步查哪里：

| 码 | 含义 | 动作 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 数据过长 | 查代码 |
| **2** | **该地址无应答**（器件不在这个地址） | 查器件供电、焊接、地址跳线 |
| 3 | 数据无应答 | 查从机状态与总线 |
| 4 | 其它 | 查总线状态 |
| **5** | **总线超时**（事务根本没法完成） | **停止查地址，直接查物理层接线** |

**判错码 = 白干**。看到 5 还去翻地址表，是最常见的时间浪费。

## 二、上拉归属

每条总线要分开看上游与下游，两件事互相独立：

- **上游（主控 ↔ 复用器/转换器）**：成品模块通常板载 10k，不需再加。
- **下游（复用器 ↔ 从机）**：SSD1306 等模块通常板载上拉，不需再加。
- **禁重复加**：再往 SDA/SCL 补 4.7k 会把等效阻值拉得过低，逼近从机低电平驱动极限（SSD1306 标称 sink ≈ 3mA）。
- `link-probe` 实测只证明**它那一侧**有上拉，不能证明另一侧有——两件事互相独立，不能互相推断。

**上拉并联量化**（三块同址屏经 PCA9548A 的场景）：

| 配置 | 等效上拉 | 判断 |
|---|---|---|
| 三块屏各 4.7k 仅屏上拉 | ≈1.57k | 尚可但已偏低 |
| 三块屏 4.7k + 模块八路各挂 10k | < 1k | 逼近 SSD1306 sink 极限 |

因此采用「一次只选通一路」：选通道 → 刷屏 → 断开 → 下一路。任一时刻只有一块屏的上拉在线，既不存在并联，又能故障隔离、逐通道观测应答。

## 三、事务分块

ESP32 Arduino `Wire` 单次事务缓冲约 128 字节（含控制字节与地址字节余量），因此：

- SSD1306 每页 128 列按 `kChunkPayload = 64` 字节载荷拆 2 次事务，一轮刷新 8 页 × 2 = 16 次事务。
- 1602 的 `sendByte()` 一次事务推 4 个状态字节（`hiData|E=1`、`hiData`、`loData|E=1`、`loData`）写完一个字节——朴素写法一字节 4 次事务，合并后写 1 字符 = 1 次事务，整屏 32 字符从 128 次降到 32 次。
- 扫描阶段速率降到 100kHz 而非 400kHz：扫描优先容错。

## 四、超时与从机离线

所有驱动统一 `Wire.setTimeOut(50)`——总线卡死不无限等待。这个 50ms 就是从机离线时的阻塞来源：屏不在线时每页 `endTransmission()` 阻塞到超时，8 页 × 2 次事务 ≈ 800ms，足以把 1 秒节拍带偏。

解法见 `SKILL.md` §2.4.2：探测失败后刷新函数直接返回，不发任何事务。实测屏缺席仍 45 tick / 45 秒 = 1.0000 tick 每秒，无漂移。

## 五、案例一：GPIO1/2 上 I2C 完全不通

**现象**：OLED 接 GPIO1(SCL)/GPIO2(SDA)，0x3C 无应答；`i2c-scan` 扫 0x08–0x77，每个地址 `endTransmission()` 都返回 **5**；`bus-probe` 读两脚 `pullup=HIGH float=HIGH`（高阻态，外部无器件驱动或上拉）。

**根因**：这两个脚在本板不能用于 I2C。换 GPIO4/5 立刻通。

**教训**：全段 5 = 物理层问题，与地址无关。当时若继续翻地址表就是白干。

## 六、案例二：1602 背包假象（判读会骗人）

这是本仓库最贵的一条教训，完整过程值得记住。

**背景**：1602A + PCF8574 背包模块，按 3.3V 供电接线（背包 VCC 接 3V3，上拉随之变 3.3V，无需电平转换）。

**观测**：

1. 背光亮（VCC/GND 已到背包）；
2. `link-probe` 两线 `pullup=HIGH float=HIGH`（外部上拉在线）；
3. `i2c-scan` 0x08–0x77 **零应答且零 `[ERR]` 行**（总线能正常完成事务，但无器件应答）；
4. SDA/SCL 对调仍无应答；
5. 主程序每 5 秒 `[retry] probing LCD again...`，0x27 与 0x3F 均不应答。

**当时收敛到的结论**：背包模块硬件故障——上拉正常、供电正常、全段无应答，接反与总线拉死都已排除。

**反证**：把 I2C 背包整块拔下来，**背光仍亮、两线仍读 HIGH**。背光由背包上 PCF8574 的 P7 驱动，器件真拔掉不可能还亮。只有两种解释且都指向同一件事：排针从头到尾没插进面包板，或背包与屏体 16 针并口虚接——电流从未经过 PCF8574。

**结论**：

- 「背光亮 = 供电到位」这条判读在本机**不成立**；
- 上拉读到 HIGH 也不能证明 SDA/SCL 真接到了背包；
- 屏体上那 4 个脚一般只是屏体自己的引出 + 背光限流，背包没插到底就会出现「背光亮但器件不在总线上」的假象。

**正确的第一步**（不需要 ESP32，万用表就行）：量背包自身排针与屏体对应针之间的通断，开路就重新压接/补焊 16 针并口，再谈地址、总线、固件。**通断确认之前，那些全是无效劳动。**

**与错误码的关系**：返回 5（超时）才会打 `[ERR]` 行；本次一行 ERR 都没有，说明总线电气与主控收发都正常。看到全是「无应答」时不要再查主控侧，直接查器件供电与焊接。

## 七、5V 电平冲突

1602 要 5V 才有足够对比度（3.3V 下余量很小、字很淡），而 ESP32-S3 IO 非 5V 耐受（绝对最大输入 VDD+0.3V ≈ 3.6V）。关键在 PCF8574 背包板上 4.7k 上拉挂在**背包 VCC** 上：背包接 5V，则 SDA/SCL 的 HIGH 就是 5V，直连主控会经 ESD 保护二极管灌电流**慢性损坏引脚（不当场冒烟）**。

**正确做法**：背包 VCC 接 5V；SDA/SCL 经双向电平转换模块再进 GPIO4/5；两侧共地。模块选型：

- 优先 **MOSFET 型（BSS138）** 或 **PCA9306**；
- **不用 TXB0104**——方向检测在开漏总线上可能振荡。

**上电前判据**：万用表量背包 SDA/SCL 对 GND 的空闲电压，应等于转换模块 LV 侧 3.3V；量到 5V 先别接主控。

**另一条安全线**：跑一阵 IO 失灵/发热 = 立即断电，这就是电平不匹配在慢性损坏。

## 八、PCF8574 与 HD44780 速查

| 项 | 值 |
|---|---|
| 地址 | 0x27（A0/A1/A2 全接地最常见）或 0x3F（PCF8574A） |
| 速率 | 100kHz（PCF8574 标称上限；400kHz 常能跑但非规范） |
| 位映射 | P0=RS(0x01)、P1=RW(0x02，恒 0 只写不读)、P2=E(0x04)、P3=BL(0x08 背光 1=开)、P4–P7=D4–D7 |
| DDRAM | 每行 40 字节，第 1 行 0x00、第 2 行 0x40 |
| 对比度 | 背包蓝色电位器调 V0 |
| 影子寄存器 | PCF8574 无读改写能力，驱动内部维护 `shadow_`，每次写覆盖全 8 位 |
| 清屏耗时 | 1.52ms |

时序常量：`kPulseUs=1`（E 脉冲 >450ns）、`kCmdDelayUs=40`（命令间隔 >37µs）、`kInitDelayMs=5`（上电初始化 >4.1ms）、`kClearDelayMs=2`、`kLongCmdUs=1600`。

初始化序列：`delay(5)` → `writeNibble(0x03)×3`（间隔 5ms/200µs/200µs）→ `writeNibble(0x02)` 切 4 位 → `sendByte(FUNCTION_SET|0x08)` → `sendByte(DISPLAY_CTRL|0x04)` → `clear()` → `sendByte(ENTRY_MODE|0x02)`。

写整行补空格到 16 列，防上一帧残影——LCD 掉电后画面会保留，不补空格就会看到旧字符尾巴。
