# 标签台账与门禁守卫（ledger-and-gates）

> 状态不靠人记，靠标签表达；门禁清单只有一个事实源。本文件是 `SKILL.md` §2、§5、§6 的执行面细则。

---

## 1. 标签就是任务队列

| 标签 | 含义 | 谁来动 | 离开条件 |
|---|---|---|---|
| `needs-repro` | 缺可粘贴的复现命令 | 发现者补齐 | 正文出现能跑通的复现命令 |
| `needs-fix` | 已确认，等代码线修 | 任一空闲会话 | 挂上 PR 编号 |
| `needs-review` | PR 已开，等新上下文评审 | 派发脚本 / 主控 | 出现三段齐全的结论 |
| `needs-live-verify` | 已合并，等真机回签 | 发现者或新会话 | 回签记录贴出且结论通过 |
| `blocked` | 被另一张单卡住 | 任意 | 依赖单关闭后摘掉 |

规则：

- **谁空闲谁捡**：空闲会话按标签顺序（`needs-fix` → `needs-review` → `needs-live-verify`）自取，不需要开会同步；
- **数字就是待办清单**：每次报告只报各标签的计数，不报状态描述；
- **一张单同时最多两个标签**，超出的标签表示这张单没拆干净；
- **标签不表达进度百分比**——进度体现在「有没有 PR、门禁绿不绿、有没有回签」。

## 2. 门禁清单的唯一事实源

门禁命令写在仓库 `scripts/gates.json`（或等价的机器可读清单），**每个 PR 都读它**，文档里只写「门禁见清单」，不复制命令。

```json
{
  "gates": [
    { "name": "lint", "cmd": "<lint 命令>", "required": true },
    { "name": "typecheck", "cmd": "<类型检查命令>", "required": true },
    { "name": "test", "cmd": "<测试命令>", "required": true },
    { "name": "build", "cmd": "<构建命令>", "required": true }
  ]
}
```

纪律：

1. **改清单 = 改规矩**：放宽或删掉一条门禁，必须单独开一张单并走评审（`SKILL.md` §10 第 3 条）；
2. **文档不复制命令**：清单与文档不一致时以清单为准，并立刻修文档；
3. **PR 正文贴的是清单的输出**，不是每张 PR 自己发明的命令；
4. **清单里不写环境变量与凭据**——命令自取环境，清单只写命令本身。

## 3. 派发脚本的形态

用纯标准库脚本生成评审派发文案。要求：

- 输入只有 PR 编号（与可选的仓库标识）；
- 输出只含：PR 编号、分支名、改动文件清单、门禁命令清单、结论三段模板；
- **默认不给 PR 正文**，也不给 issue 正文；
- 输出可被直接粘贴进新会话作为任务说明；
- 脚本失败时报错退出，不输出半截文案。

脚本落在仓库 `scripts/`，形态要求见 `skill-authoring` 的 D7（Python 3 纯标准库单文件、kebab-case 命名）；`SKILL.md` 只写用途，不写命令行。

## 4. 每轮收口的三个数字

| 数字 | 从哪读 | 阈值（超出就停一轮） |
|---|---|---|
| 存活 PR 数 | 开着的 PR 列表 | 上限由项目自定；实测基线 10，超出说明合并在堵 |
| 合并间隔中位数 | 合并时间戳两两之差 | 基线 15.1 分钟；持续翻倍说明门禁在主干上反复红 |
| 单小时合并峰值 | 每小时合并数 | 基线 9 次；断崖式下跌说明评审队列积压 |

数字异常时的处置顺序：先看 `needs-review` 积压 → 再看门禁红率 → 最后才考虑放宽并发上限。放宽并发永远不是第一个选项。
