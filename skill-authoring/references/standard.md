# 技能规范条文（standard）

> 本文件是条文的**完整定义**（含范围、判据、反例）。`SKILL.md` §5 是红线的一句话形态，供执行时扫读；两者冲突时以本文件为准。
> 三档：**M = 必须**（违反即禁止落地）／**D = 默认**（可偏离，但偏离必须在 `references/version.md` 或 `docs/adr/` 留下理由）／**P = 禁止**。
> 「句子该怎么写」不在这里——那属于上游技能 `writing-for-agents`。

---

## M —— 必须

### M1 目录名 = `name`，只用小写英文与连字符

- **判据**：目录名与 frontmatter `name` 逐字相同；匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`。
- **理由**：技能按目录名被索引；两者不一致时，按名字加载会落空，而错误只在运行时才暴露。
- **反例**：`Commit_Report`、`commitReport`、`提交报告`。

### M2 骨架：六个必备构件 + 两个条件性构件，顺序固定

| # | 构件 | 形态 |
|---|---|---|
| 1 | frontmatter | YAML，六键按 M3 的顺序 |
| 2 | H1 标题 | `# <name>：<一句职责>` |
| 3 | 触发加载检查块 | H1 之下、正文之前的引用块；句式照 `templates.md`，换成该技能的触发词与最危险的动作 |
| 4 | 定位段 | 以「定位：」开头的普通段落：与谁分工、核心机制一句话、指到 `references/version.md` |
| 5 | 流程章节 | `## 1.` 起的正文主体，按阶段分章；每步给出判据与停止条件 |
| 6 | 完成后报告 | 最后一个 H2；列出必须报告的内容，穷尽且可勾选 |

| 条件性构件 | 何时必须有 | 位置 |
|---|---|---|
| 何时使用 | 触发分支 ≥ 2 个 | 必须是第 1 章 |
| 安全边界（硬性，任何路径下均适用） | 技能会执行不可逆动作（写文件、提交、推送、部署、删除、对外发消息） | 「完成后报告」之前 |

- **判据**：拿 `templates.md` 的骨架模板逐项对照；两个条件性构件各自能说出"为什么出现"或"为什么不需要"。
- **理由**：构件固定 = 任何技能都能被同一套脚本检查、被同一个读者按同一顺序找到东西；构件条件化 = 不给单一分支的技能硬塞空章节（空章节付 context load 却什么也没说）。

### M3 frontmatter 六键齐全、顺序固定

顺序：`name` → `description` → `agent_created` → `version` → `last_updated` → `author`。

- `agent_created: true` —— 本仓库自建技能一律为 `true`。
- `author: siungolai`
- `last_updated` 是**最后修订日期**，不是创建日期。
- 可选扩展只能加在六键之后：`license`、`platforms`、`metadata.*`（宿主专属元数据，如 `metadata.hermes`）。
- **判据**：键顺序逐字一致，无重复键，无未列举的键。
- **反例**：漏 `agent_created`；把 `version` 写在 `name` 之前；把 `license` 插在 `version` 与 `last_updated` 之间。

### M4 `description` 必须写清触发场景

- **句式**：`<职责>：<触发情形 1>、<触发情形 2>…时使用。`
- **判据**：把触发情形那句删掉，句子只剩职责、无法回答"什么时候用"——这样的写法不合格。
- **理由**：`description` 是唯一每轮都付 context load 的字段，它是技能的顶层 pointer；写不清触发场景，就等于技能不存在。
- **反例**：「本技能是一个强大的自动化工具，帮助用户高效完成任务。」（没有触发场景）

### M5 必须有 `references/version.md`，每次修订必须 bump 并追加一行

- **形态**：见 `templates.md`；按时间倒序；表头 `| 版本 | 日期 | 变更 |`。
- **判据**：`version` = 表首行版本；本次修订在表里有一行且日期 = `last_updated`。
- **理由**：版本表是"这份技能为什么变成现在这样"的唯一线索；与 frontmatter 对不上时，读者无法判断手上的是哪一版。

### M6 章节编号全阿拉伯，`§` 引用只用阿拉伯数字

- H2：`## N. 标题`（N 从 1 起连续）；H3：`### N.M 标题`（M 在章内从 1 起连续）。
- 引用：`§N` 指第 N 章；`§N.M` **先解析为 H3 编号 `N.M`**，该 H3 不存在时再解析为第 N 章内某个有序列表的第 M 项。
- **永不写** `§五` 这类中文数字引用，也不用中文数字编章节号。
- **判据**：全文 grep `§`，每个引用都能唯一解析到标题或列表项；每个 H2/H3 都有编号。
- **理由**：`§` 的全部价值是"短且唯一可解析"。本仓库曾经四种写法并存（`§6` 位置引用、`§2.1` 指 H3、`§五` 指中文数字章、`第六节 §6.4` 混用），并已产生真实的坏引用。

### M7 正文所有引用必须真实存在

- 覆盖四类：`§` 编号、`references/…` 与 `docs/adr/…` 路径、「见 `X` 技能」的 X、以及引用到的文件名。
- **只查命名到具体文件的路径**：`references/standard.md` 这类必须存在；目录式与省略式写法（`references/`、`references/…`、`docs/adr/`）是版面约定而非对本技能磁盘状态的断言，不做存在性检查——规范类技能会用它泛指「别的技能里的那个目录」。
- 跨技能引用必须给**路径回退写法**：优先 `~/.dsh/skills/<name>/SKILL.md`，不存在时读仓库内的 `<name>/SKILL.md`；两者都没有则报告并转人工确认。
- **判据**：`check-skills.py` 的第 4、5、6 项全绿。
- **例外（历史记录不改写）**：`references/version.md` 与 `docs/adr/` 里的历史条目描述的是**当时**的状态——其中出现的旧章节号、旧版本号、已删除的文件名一律保留原样。改写它们等于伪造历史。
- **范围外**：宿主专属元数据里的字段（如 `metadata.hermes.related_skills`）不算正文引用，不做存在性检查。

### M8 新建技能前必须查重

- **判据**：能写出「本技能与既有技能 `X` 的分工依据」——谁管什么、边界在哪。写不出来，或发现是同一件事的两种说法，就该并进既有技能。
- **理由**：职责重叠的两个技能不会互相纠错，只会在同一情境下各自给出不同答案，而用户无从判断该信哪个。
- **反例**：新建 `git-commit-helper`（与 `commit-report` 重叠）。

### M9 凭据与私有信息零入库

- **范围**：`deploy-report/references/publish-check.md` 的全部内容——凭据与私钥、token 与 api key、环境变量实际值、原始 IP 与内网地址、带用户名的 host 别名、私有文件的真实路径细节。
- **判据**：推送前跑一遍 publish-check，命中 0。
- **理由**：本仓库是公开仓库，推出去即视为永久公开，撤回无效。

### M10 推送前必须跑 publish-check，并在审阅展示中声明结果

- **声明格式**：`已跑 publish-check：扫描 N 个文件，命中 0`。
- **判据**：审阅展示里能找到这句；有命中时先修复再复检，不得带着命中推送。
- **单一事实源**：只写指针，不把 `publish-check.md` 的条文复制到别处（P6）。

### M11 改动后必须同步到 `~/.dsh/skills/<name>/`

- 仓库是**唯一编辑现场**：所有改动先在仓库里做，再同步过去。
- 同步是**内容同步**，不是增量添加：新增与修改的文件复制过去，仓库里删掉的文件在副本里也删掉。
- **判据**：两侧 `SKILL.md` 的 frontmatter `version` 一致。
- **范围**：只同步本仓库的自建技能；上游技能与非本仓库技能（见 `external-skills.md`）不动。
- **理由**：本仓库曾发生单向漂移——`commit-report` / `deploy-report` 的安装副本比仓库副本多一行 `disable-model-invocation: false`，同一技能在两处内容不同。

## D —— 默认（可偏离，偏离必须在 `references/version.md` 或 `docs/adr/` 留下理由）

### D1 一个技能只做一件事

**判据**：`description` 里出现两个互不相关的职责 → 拆成两个技能。

### D2 `references/` 只放"部分分支才需要"的材料

**判据**：把 `references/` 全部删掉，`SKILL.md` 的主流程仍然可执行；正文与 `references/` 不得重述同一含义（正文写 pointer，不写副本）。

### D3 版本号三段式

| 级别 | 触发条件 |
|---|---|
| `+patch` | 无行为变化：错字、编号重排、坏引用修复、措辞调整 |
| `+minor` | 条文增删、结构与章节重组、新增或删除章节 |
| `+major` | 职责、触发范围、安全边界发生变化 |

存量两段式版本号（`1.4`）在下次修订时补成三段（`1.4.1`）。

### D4 派生面必须一致

`references/version.md` 表首行、README 技能表版本、frontmatter `version` 三处相同；`last_updated` = `version.md` 末次条目日期。偏离须在完成后报告里说明原因。

### D5 README 必须跟上

技能增删改后：技能表加/改一行（名称链接 / 版本 / 简介 / 结构）；「目录结构」块与该技能磁盘内容一致；徽章 `skills-N` 的数字 = 实际技能数。

### D6 `CONTEXT.md` 与 `docs/adr/`

- 有领域特有术语 → `CONTEXT.md`（只定义语言，不写实现细节）；多语境时用 root `CONTEXT-MAP.md`。
- 决策**三条同时成立**才写 ADR：难以反转、没有上下文会令人惊讶、是真实权衡的结果。否则不写。
- ADR 放 `docs/adr/`，连续编号 `NNNN-<中文标题>.md`，按需懒创建。

### D7 自带脚本的形态

放 `<skill>/scripts/`，Python 3 纯标准库单文件，kebab-case 命名；`SKILL.md` 只说明用途与何时用，不写调用命令行。

### D8 语言分工

英文：目录名、文件名、frontmatter 键、命令、技能名、标识符。中文：标题与正文。

### D9 完成后报告必须交代

改了什么（文件清单）、版本变化（旧→新 + 级别）、自检结果（脚本 + publish-check）、同步结果、遗留项。五项齐全，缺项要说明为什么缺。

## P —— 禁止

### P1 禁止写 `disable-model-invocation: true`

DSH 没有手动调用面板；写了 `true` 会让技能永远加载不了。要让模型可调用就**省略这个键**，也不要写 `false`（那是 no-op，只增加一个需要两边一致的字段）。

### P2 禁止中文数字章节号与 `§五` 式引用

见 M6。

### P3 禁止凭据、内网地址、带用户名的 host 别名、私有路径细节

见 M9。公开仓库不可撤回。

### P4 禁止创建与既有技能职责重叠的新技能

见 M8。

### P5 禁止在 `CONTEXT.md` 里写实现细节

它只定义语言：术语、释义、`_Avoid_` 的同义词。实现、流程、参数都不属于它。

### P6 禁止把本规范的条文复制到别处

其他技能或文档要引用本规范时，只写 pointer（`skill-authoring` 的 M/D/P 编号），不复制条文。同理，本规范也不复制 `publish-check.md`（M10）、`writing-for-agents`（写法）、`domain-modeling`（CONTEXT / ADR 格式）的条文。

### P7 禁止 `references/` 里的孤儿文件

`references/` 下每个文件都必须在 `SKILL.md` 正文里有一个 pointer；没有 pointer 的文件读者永远不会加载到，等于不存在。
