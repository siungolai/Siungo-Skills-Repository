# 游戏设计文档审计模式

从模拟/养成类游戏的策划案审计中提炼的游戏专属模式。随更多游戏项目审计逐步填充。

## 替换点提示

- **数值平衡 → 属性表**：把「课程求和 → 属性合计」换成你项目里的实际聚合单位（课程/装备/技能/关卡）。
- **可达性**：阈值对照「累计最大值 vs 门槛」的模式适用于任何带解锁条件的系统。
- **经济闭环**：替换「学费/兼职/商店」为你项目的实际消耗-收入端。
- **状态机**：学习/工作/放松/游戏/考试只是样例状态集，换成你项目的实际状态集。
- **大表生成**：适用于任何由脚本批量生成的条目表（课程/岗位/装备/技能/图鉴）。
- **防刷论证**：任何奖励系统都需要「只发首次 / 绑定到消耗动作 / 期望值为负」这类证明。

## 数值平衡

### 属性表
- 在代码中构建每门课的 `(name, int, gla, str)` 元组
- 按学阶求和；与文档中**每个**声称的合计比对（原始策划案 + 标注的"实算" + 真实合计）
- 文档中常同时流转 3 套以上数值——必须全部显式核对
- 注意：脚本核验过的累计求和**不应**被直接改数去凑阈值（在缺少底层条目表的情况下会制造新的漂移）

### 可达性
- 可达最大属性值（由课程求和得出） vs 解锁阈值（岗位/证书要求）
- 阈值高于最大值 = 内容永久不可达 = P0
- 当内容被多个消费方共享（学位/学科从共享池中各取子集）时，按**每个消费方自己的子集**验证——全局求和过关会掩盖某个子集不达标的学位

### 经济闭环
- 日耗散（衰减率 × 24h） vs 免费动作配额 vs 商店价格 vs 收入速率
- 警惕先有鸡还是先有蛋：学费定价所在档位，在你付得起学费之前根本到不了
- 后期检查：交完所有学费/一次性购买后，结余是否只增不花（金币溢出 → 玩家失去动力）

## 状态机
- 状态互斥：任何两个状态不得共存（学习/工作/放松/游戏/考试）
- 状态-边动作：考试中能喂食/购买吗？放松中能开始活动吗？
- 冷却语义：共享冷却 vs 独立冷却；每日上限
- 结算间隔：每 30 分钟、完成时、取消时——每种都需要定义明确行为
- 反作弊：分数/客户端上报值需要服务端校验

## 大表生成
- 在代码中构建所有行，写盘前验证（分组计数、全局名称唯一、ID 连续、交叉引用、各档位值域）
- 重新解析写出的文件，确认落盘数量
- 超大块替换：用 write_file 整文件重写，别用脆弱的 N 行补丁
- ID 用档位前缀 + 序号（如 `A01`–`Z16` 或类似字母前缀 + 序号），分组调整不会破坏键

## 防刷论证
- 只发首次事件奖励（按证书/按岗位发里程碑奖励会让曲线爆炸）
- 影响经济的动作必须绑定到消耗动作，不能绑定到免费动作
- 比赛/报名费必须让普通玩家期望值为负、精英为正（激励属性培养）
- 扭蛋保底 + 图鉴收集驱动重复投入，但不产生无上限收入

## 脚本陷阱

- `f"...{'✅' if re.search(r'\| X \|', s) else '❌'}..."` → `SyntaxError: f-string expression part cannot include a backslash`。预编译成变量（`pat = re.compile(r'\| X \|')`），用 `pat.search(s)`。
- 锚定台账计数：对**整篇**文档数 `^(\d+)\. \*\*` 会连带匹配到未来规划的编号项。先按 `## ⚠️` 切分，**再**在台账段内计数。
- 生成的大表名称唯一性：写盘前 `assert len(set(names)) == len(names)`。
- 回读正则必须锚定：`^### ([\u4e00-\u9fff]{2,3} [A-Z]{2})$`——宽泛模式会把数字子章节误匹配成假条目。
