# 发布前敏感信息自检清单（publish-check）

> 适用于本技能（以及仓库内任何技能）文件**提交/推送前**的强制自检。公开仓库一旦推送即视为永久公开，撤回无效——宁可多删，不可留险。本清单与 deploy-report SKILL.md §8.1 配套使用。

## 一、文本扫描（在将提交的全部文件上执行）

对 SKILL.md、references/、scripts/、README 等将提交文件做正则扫描，命中即停查：

```regex
-----BEGIN [A-Z ]*PRIVATE KEY-----
BEGIN (RSA |EC |OPENSSH |DSA )?PRIVATE KEY
password\s*[=:：]\s*\S+
passwd\s*[=:：]\s*\S+
secret\s*[=:：]\s*\S+
(token|api[_-]?key|apikey)\s*[=:：]\s*\S+
authorization\s*[=:：]\s*
Bearer\s+[A-Za-z0-9._~+/=-]{10,}
\.(pem|key|p12|pfx|jks|keystore)(['"\s]|$)
```

注意：模板文件中的占位符（如 `<password>`、`example.com`、`%ENV_VAR%`）不算命中；正则命中的**真实形态**才算（含真实域名后缀、明显非占位符的值）。拿不准就人工确认。

## 二、文件级检查

1. `git status`：将提交列表逐文件过目——不应包含部署档案实例（deploy-profile 类）、凭据文件、私有工具目录。
2. `git check-ignore <档案文件>`：档案必须返回已忽略；未忽略 → 先补 `.gitignore` 再继续。
3. 检查是否误把整目录（`.ssh/`、`.ssh-tool/`、`.env` 等）加入提交。
4. 检查引用：SKILL.md/references 中提到的路径是否存在指向私有文件（user.md、密钥库等）——只允许"引用路径模式"（如 `.ssh-tool/ssh-exec.js` 这类工具形态描述），不允许携带其内容或真实文件路径细节。

## 三、内容级检查

1. 不出现：字面密码/token/key/私钥/cookie/监控 key；`ssh://user:pass@` 形态连接串；带口令的连接串。
2. 不出现：环境变量实际值（只允许变量名）。
3. 主机标识：域名可公开（公网本就可查）；**原始 IP、内网地址、带用户名的 host 别名**尽量不出现或改指针。
4. 示例与实例素材：真实示例只保留"公网可查事实"（域名、服务名、备份策略、验证端点结构），凭据类与私有路径细节剔除。
5. 确认没有"看起来像密钥"的占位符被真实值替换过（如 `<token>` 被填成真值后忘记还原）。

## 四、推送前终检

1. 逐文件重读一遍 diff（`git diff --cached`），不只看文件名。
2. 对历史提交是否含敏感信息的自查：一旦发现历史曾误含 → 视为已泄露：立即轮换相关凭据（改密码/换 key），而不是只删文件。
3. 本清单执行结果在审阅展示中声明（"已跑 publish-check：扫描 N 个文件，命中 0"）。

## 五、自检记录模板

```markdown
## publish-check 结果（<日期>）
- 扫描文件数：N
- 正则命中：0（如命中，列出文件与行并修复后再检）
- git 忽略检查：deploy-profile 类文件已忽略（是/否）
- 内容级检查：通过（域名外无主机标识；无凭据字面值；示例已脱敏）
- 结论：可以提交 / 需修复后复检
```
