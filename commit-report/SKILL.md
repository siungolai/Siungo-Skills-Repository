# commit-report：审阅门式 Git 提交

定位：与内置 /commit 命令互补——本技能以**强制审阅门**为核心，用户看到变更总揽与 commit 信息全文并明确确认后，才执行提交。**push 默认不执行**，仅在用户明确选择时进行。

## 一、目标仓库定位与前置自检

1. **确定目标仓库**：当前目录为 git 仓库则直接采用；否则向用户列出候选或请求指定仓库路径／URL，选定后继续流程；用户拒绝指定时终止。
2. 空仓库（无任何提交历史）：跳过"匹配既有风格"，按通用规范生成首次提交信息，并在审阅中注明"首次提交，无历史风格可匹配"。
3. 无任何变更（工作区与暂存区均干净且无未跟踪文件）：报告"无事可提交"，结束，不进入审阅。
4. detached HEAD 状态：提示先切换或新建分支，不执行任何操作。

## 二、分析阶段

1. **仓库状态**：读取当前分支名、与上游的领先／落后关系。
2. **风格匹配**：读取最近 10 条提交的主题行，归纳并输出三要素——前缀风格、语言、主题行模板（如 `Add <skill> skill`、`docs: <主题>`）；本次匹配到的模板须在审阅中注明。无明确风格可循时，默认 conventional commits、简体中文。
3. **变更盘点**：按三组分类——已暂存／未暂存／未跟踪；同一文件同时存在已暂存与未暂存变更时合并为一行，状态标注"部分暂存"。
4. **改动摘要**：变更类型枚举为新增／修改／删除／重命名四类，每文件一行（类型＋核心内容），规则：
   - 单文件 diff 超过 300 行：只读头部与 `diff --stat`，标注"大改动（概要）"；
   - 二进制文件：标注"二进制文件（大小 X）"；
   - 未跟踪新文件：读文件头部判断性质后写摘要；
   - 变更文件总数超过 20 个：低重要性文件按目录聚合为一行并附统计（如"src/ 下 32 个文件，+512 -96"），重要文件（配置、入口、依赖清单等）仍单独列出。
5. **风险预警**（均不阻断，由用户在审阅中决定剔除）：
   - 敏感文件：文件名匹配 `.env`、`*.key`、`*.pem`、`*.p12`、`*.pfx`、`*.jks`、`.netrc`、`.npmrc`、`credentials`、`secret`、`*token*`、`id_rsa` 等模式时，**加粗警示"疑似敏感文件"**；
   - 大文件：单文件超过 1MB 时标注"大文件（X MB）"。

## 三、审阅展示（固定模板，缺项注明"无"）

1. **仓库与分支**：仓库标识（路径或 owner/repo）、分支名、与上游关系；
2. **commit 信息全文**：主题行＋正文，风格与既有提交一致；
3. **变更总揽表**（三组分组，部分暂存合并呈现）：

   | 状态 | 文件 | 改动摘要 |
   |---|---|---|

4. **风险预警**（敏感文件加粗、大文件标注，如有）；
5. **回应路径**（固定文案）：

```
请回复：
① 确认提交（仅 commit，不 push）
② 确认提交并 push（推送至当前分支上游）
③ 需要调整（改 commit 文案 / 剔除文件 / 其他）
```

## 四、回应判定

- **确认判定（操作性定义）**：凡包含提交意向且不含任何修改意见的明确指令，均视为确认——如"确认提交""全部提交并推送""直接提交"等；上文枚举仅作示例。纯模糊应答（如单独一个"嗯"）不构成确认，需重新征询。
- **回复①** → 按确认范围执行 `git add`（默认全量变更；用户点名剔除的文件排除在外）→ `git commit`（HEREDOC 格式书写提交信息）。
- **回复②** → 同上执行 commit，随后 push 至当前分支上游；当前分支无上游时，先追加确认是否执行 `git push -u origin <分支名>`，确认后才执行。
- **回复③** → 按反馈修订（commit 文案或提交范围），重新完整展示审阅；修订循环次数不限，由用户主导。
- **用户发起时明说"跳过审阅直接提交"** → 不展示直接执行（当次显式指令优先），但第五、六节仍然全部适用。

## 五、执行通道与降级

1. **默认通道**：本地 git 命令行（add → commit → push）。
2. **降级通道**：git 传输故障（HTTP2 framing 错误、CONNECT 5xx、连接超时、Empty reply 等）时，改用 `gh api` 的 git data API 单次提交，四步：`git/blobs`（base64 编码）→ `git/trees`（携带 base_tree）→ `git/commits`（message + tree + parents[]）→ `PATCH git/refs/heads/main`。两个已知陷阱：MCP github 连接多为集成令牌，写入常返回 403（not accessible by integration），写操作一律用 gh CLI；`gh api` 布尔字段必须用 `-F`（`-f` 会把 false 当字符串导致 422）。
3. **降级约束**：降级只改变传输手段，不改变审阅确认过的内容——仍为单次 commit、同一 message、同一文件范围；ref 更新 force=false。
4. **空范围防护**：执行前校验确认范围非空；剔除后为空则报告并回到审阅，不产生空提交。

## 六、安全边界（硬性，任何路径下均适用）

1. 禁用 `--no-verify`；pre-commit 钩子失败时报告原因并停止，不绕过。
2. 禁止 force push；禁止 amend 已推送的提交。
3. push 被远端拒绝（non-fast-forward）或网络失败：只报告差异与建议（如先 pull），不自动 pull／rebase／重试。
4. 不擅自新增或删除文件，不改动用户未确认范围之外的内容。
5. commit 信息语言跟随仓库既有风格；无历史可参考时使用简体中文。

## 七、完成后报告

提交（及推送）完成后，向用户报告：

1. **commit 哈希**（完整 SHA）、主题行、作者、时间；
2. **变更统计**：files changed / insertions / deletions；
3. **推送验证**（若执行 push）：远端分支最新提交 SHA 与本地一致；有条件时附关键文件 blob SHA 比对结果；
4. **执行通道说明**（git 或降级通道），供追溯。
