# 托管与可见性判定

`§1.6` 的实施细则，服务于 `§2.5`、`§3.3`、`§6.7`。回答一个问题：**这次要落地的提交，目标是公共服务器还是私人服务器？** 只有「私人托管 ＋ 私有仓库」才放宽隐私口径；凭据口径与托管无关，永远不放宽（见 [`privacy-scan.md`](privacy-scan.md) §1）。

## 1. 判定顺序

两步，顺序不能换：先判**托管性质**，再判**仓库可见性**（后者只在私人托管下才需要）。全程零 API 依赖（理由见 §7）。

1. 取上游远程 URL：`git remote get-url <远程名>`（默认 `origin`；场景 B 取 `@{u}` 对应的远程）。
2. 判托管性质（§2）→ 公共托管 / 私人托管 / 未确认。
3. 判仓库可见性（§3）——仅私人托管时执行。
4. 结论写进审阅单（§5）。

## 2. 托管性质

### 2.1 公共托管

host 命中下列清单（大小写不敏感；`:端口` 不影响判断）：

`github.com`、`gitlab.com`、`gitee.com`、`bitbucket.org`、`codeberg.org`、`git.sr.ht`

命中即**公共托管**，**不再看仓库是不是 private**——理由见 §6。

### 2.2 私人托管

命中下表任一条即可：

| # | 证据 | 例 |
|---|---|---|
| 1 | host 是 IP 字面量（**含公网 IP**） | `git@203.0.113.7:/srv/git/app.git` |
| 2 | 无点主机名，或以 `.lan` `.local` `.internal` `.home` `.corp` 结尾 | `gitlab`、`nas.local` |
| 3 | 本地路径：`file://`、盘符、UNC、裸目录 | `file:///srv/git/app.git`、`X:/repo`、`\\nas\git` |
| 4 | 域名解析到内网或环回地址 | `git.home.internal` → `192.168.x.x` |
| 5 | 仓库里写了声明 `git config --local siungo-remote.private true` | 自建域名走公网，但确实是自家服务器 |

**第 1 条是主证据**。公共托管只用域名，没有哪家让你用裸 IP 访问 GitHub；所以一判到 IP 字面量就按自建处理，不必再去比对内网段——公网 IP 的自建服务器正是这条要接住的。

第 4 条需要一次解析（`getent hosts`、`nslookup` 或等价手段）。解析不出来就**跳过这一条**，不要因为解析失败而改变判定结果。

### 2.3 未确认

host 是**未命中白名单的域名**、解析不到内网地址、仓库也没写声明（例：`git.siungo.example`、某个第三方自建 GitLab）。**按公共托管处理**（fail-closed），审阅单注明「托管性质未确认，已按公开口径」。

解除路径二选一：在仓库里写一次声明键（`git config --local siungo-remote.private true`），或在回复里明说「这是我自己的服务器」——后者只对当次有效。

## 3. 仓库可见性（仅私人托管）

私人托管只证明「服务器是我的」，不证明「仓库是私有的」——同一台自建服务器上照样可能挂一个匿名可读的裸仓库。

1. **默认按私有**。
2. 跑一次**不带凭据**的探测：

   ```bash
   GIT_TERMINAL_PROMPT=0 git -c credential.helper= ls-remote <remote-url> HEAD >/dev/null 2>&1 \
     && echo anonymous-readable || echo closed
   ```

   `-c credential.helper=` 清空 credential helper、`GIT_TERMINAL_PROMPT=0` 掐掉交互询问——两者缺一，探测就会用上你已经存好的凭据，测出来永远是「能读」，等于没测。
3. `anonymous-readable` → 匿名可读 → 事实公开 → **退回严格口径**。
4. `closed`（非零退出、超时、连不上）→ 仍按私有放宽。**探测失败不等于公开**，别把没连上当证据。

## 4. 结论与放宽条件

同时满足两条才放宽：托管 = 私人托管，**且** 可见性 = 私有。

| 托管 | 可见性 | 口径 |
|---|---|---|
| 公共托管 | 任意 | 严格 |
| 私人托管 | 私有 | **放宽** |
| 私人托管 | 匿名可读 | 严格 |
| 未确认 | 任意 | 严格 |

「放宽」的含义只有一条：隐私类命中与 🟠 降为 🟡 只列不拦（[`privacy-scan.md`](privacy-scan.md) §1 最后一列）。凭据类**不参与**放宽。

## 5. 审阅单怎么呈现

`§3.3` 表格上方给一行结论＋证据来源：

```
托管判定：私人托管（IP 字面量）｜可见性：私有（匿名 ls-remote 失败）｜口径：放宽
```

证据必须写出来源，**不能只给结论**——用户要能一眼看出它凭什么放宽。没法判定的场合写「未判定，按严格走」。

**remote URL 脱敏**：URL 带凭据时（`https://ghp_xxx@github.com/...`、`https://user:pass@host/...`），审阅单只准显示 `host` + 仓库路径，凭据段一律替换为 `***`。与 `§6.8`「禁止在审阅单里粘贴真实凭据」是同一条纪律。

## 6. 为什么「仓库 private」单独不够

曾考虑用「仓库是 private 就放宽」作唯一条件，被否掉：private 只是一个开关，转到公开既不需要经过你同意，也不需要经过这次审阅；平台本身、CI、备份、协作者、将来的镜像都在数据链上。**可见性不是安全边界，只是一个暂时状态。**

自建服务器上的私有仓库至少满足「数据落在自己机器上」，这是真正的差别。所以条件是「托管私人 **且** 仓库私有」这条布尔与，而不是任何单个信号。

已知代价（已确认接受）：`github.com` 上的 private 仓库继续被拦。想放宽就把仓库迁到自己的服务器。

## 7. 为什么零 API 依赖

上面所有判定只用 `git remote get-url`、字符串处理，以及一次可选的 `ls-remote`。**不要**引入 `gh repo view`、`api.github.com`：`gh` 不一定装了（实测常见安装路径都没有），而网络抖动会让安全判定随机翻转——一个会 404 的接口不能当安全边界。

`ls-remote` 是唯一需要联网的动作，且**失败按私有处理**（§3），所以网络不可用时判定不会偏向严格或放宽的另一头。
