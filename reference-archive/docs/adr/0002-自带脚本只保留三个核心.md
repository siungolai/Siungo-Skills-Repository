# 自带脚本只保留三个核心，专用方法只写不交

技能自带三个脚本：网页转 Markdown、Markdown 链接与资源自检、目录树逐文件 sha1 对账。原理图 PDF 的位置感知抽取与位图表格识别这两项本次都反复用上了，能力最强，但**只写成方法与要点，不交代码**。理由不是它们难写，而是它们的适用面窄：PDF 文本层结构、位图网格线的坐标约定、字体编码，都随每一份原理图与每一张表而变，同一份代码换个来源就废。

三个核心脚本则相反——它们处理的对象是「结构稳定的通用形态」：HTML 页面、Markdown 链接、目录树文件。这三样在任何文档站、任何归档、任何上游仓库上都是同构的，脚本能一劳永逸地复用。而 PDF 抽取与位图识别面对的是「每一份都长得不一样的具体文档」，交代码进去等于交了一份只对这一份原理图有效的假通用工具，读者拿去用会踩坑还不知道是坑。

代价是：想复现本次那套原理图网表提取的人，得自己按方法重写一遍。接受这个代价，是因为「一份可复现的代码」和「一份读得懂的方法」在通用性上的差距远大于工作量差距——重写一次要几小时，而拿着一份不通用却看起来能用的代码去调几天的概率不低。

这也划定了技能与参考资料的边界：技能负责**方法可迁移**，references 里的实例负责**路径可参照**。两者的分工与 `references/rlcd-4.2-case.md` 的定位一致。
