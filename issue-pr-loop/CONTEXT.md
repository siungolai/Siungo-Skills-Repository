# issue-pr-loop（一单一活的并行开发流水线）

在「一个主控会话 + 多个执行会话」的语境下工作：把工作拆成可以各自独立验收的单子，让多条线并行改，每一处改动都从 PR 进主干，最后排成一条队合并。它管的是**改动入口、队列与证据**，不管代码怎么实现。

## Language

**PR（pull request）**：
唯一能把改动送进主干的通道。它同时承载五样东西：改动内容、门禁原始输出、评审结论、回签计划、单号。PR 不是「改完顺手提一下」的附属品，它是交付单元本身。
_Avoid_：提交、补丁、diff、请求合并

**主干（trunk）**：
仓库的主分支（`main` / `master` / `slim`）。它在任何会话里都是只读的：可以 fetch、可以 rebase 到它上面，不能在上面提交，更不能推上去。
_Avoid_：主分支、master 分支

**直推（direct push）**：
不经 PR 把提交送进主干。本技能里它不是「不太规范」，而是事故：门禁跑在谁的工作区、评审看的是哪个版本、回滚该撤哪一段，全部无法回答。
_Avoid_：直接提交、手工合并

**单子（issue / ticket）**：
一件能独立验收的事，装在一张 issue 里。独立性由三条同时判定：能单独跑门禁、能单独合并、能单独回滚。三条缺一就说明它其实不止一件事。
_Avoid_：任务、工单、需求（当它泛指一批工作时）

**四要素**：
一张单能被另一个会话直接开工所需的最小信息：现象、期望、复现命令、影响面。缺复现命令的单即不成立，必须挂 `needs-repro`。
_Avoid_：描述、详情

**plan 追评**：
写在 issue 下的方案评论，与 issue 正文分开；正文描述问题，plan 描述怎么改、PR 预期长什么样，复现结果作为后续评论贴原始输出。plan 是开工的凭据，聊天里的方案不算。
_Avoid_：设计方案、技术方案文档

**执行线（line）**：
一条独立的改动工作流：一个 worktree + 一个分支 + 一个会话 + 自己跑门禁 + 自己开自己的 PR。执行线之间不共享文件，也不共享会话。
_Avoid_：任务、分支、流水线

**分层（layering）**：
把本轮要派的单子排成先后次序：改同一个文件的两张单永远不同层，有依赖边的先派被依赖方。同层内全部并发，不同层互不等待。
_Avoid_：排期、优先级排序

**评审人（reviewer）**：
一个**新上下文**里的会话，与执行线不是同一个会话。它自己读 PR、自己跑门禁、必要时自己做变异实验，输出三段结论。评审人不是执行线的上级，只是独立证据源。
_Avoid_：审批人、reviewer 二遍、第二双眼睛

**三段结论**：
评审结论的唯一合法形态：结论（APPROVE / CHANGES-REQUESTED）、复核动作、证据。证据必须包含评审人自己跑出来的东西。缺任一段视为未评审。
_Avoid_：审批意见、评论、LGTM

**变异实验（mutation probe）**：
评审人为了证明「门禁真的会红」，故意把代码改成刚好越界的值，观察红的是不是预期的那些条，然后回退。它把「看起来绿」变成「证明绿」。
_Avoid_：反向测试、故意报错

**免审通道**：
只允许纯文档与纯重构走的一条窄路：PR 照开、门禁照跑，但可以免新上下文评审，条件是 PR 正文首行写明「纯文档」或「纯重构」。它免的是评审，不是 PR。
_Avoid_：例外、特殊情况、小改动通道

**合并条件（merge checks）**：
一张 PR 获准进主干前必须同时成立的七项：APPROVE 且三段齐全、最新基线上门禁全绿、只对应一张单、正文五段齐全、squash 且标题带单号、行为类用 Refs、存活 PR 数未超上限。
_Avoid_：合并标准、准入门槛

**回滚单位（rollback unit）**：
一次 `git revert` 能完整撤销的最小改动集合。squash 合并让一张 PR 在主干里就是一个提交，于是回滚单位 = 一张 PR——这也是「一张 PR 只装一件事」的真正理由。
_Avoid_：回滚点、备份

**对账（reconcile）**：
定期检查主干第一父链上每个提交是否都能追到一张带单号的 PR。它是机制而非纪律：钩子挡手滑、平台保护挡习惯、对账挡事后编故事。
_Avoid_：审计、抽查

**串行合并（serial merge）**：
同一时刻只有一条 PR 进主干。门禁必须跑在最新主干上，所以排队合并常常比并发合并更快。
_Avoid_：合并窗口、批量合并

**回签（live verify）**：
改动运行时行为的单子合并后，由**发现者或另一个新会话**在真机上复跑复现命令并贴原始输出；修复者不能给自己回签。回签通过是关闭该单的唯一条件。
_Avoid_：验收、复测、确认一下

**标签队列（label queue）**：
用标签表达状态，谁空闲谁捡，不靠人记、不开会同步。计数就是待办清单。`needs-merge` 是队列标记，不是进度条。
_Avoid_：看板、状态表

**接手六步**：
一个零历史的新会话进入并行队列的固定路径：读总纲 → 看一张已关闭单 → 看它的 plan → 看对应 PR 的评审结论 → 自己开一张单 → 派一轮评审。第六步走通即视为已接手。
_Avoid_：onboarding、新人指南
