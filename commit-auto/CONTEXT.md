# commit-auto（自动提交）

以「正常 commit 节奏」自动落盘的技能：每闭合一个**提交单元**就生成一次提交。本文件是该技能的术语表，只定义语言，不记录实现方式。

## Language

**提交单元**：
一次自动提交所覆盖的改动整体。它是一个用户可感知的交付单位，历史上等于「一个已交付的功能／一个阶段」。
_Avoid_: 变更集、改动包、changeset、patch

**提交节奏**：
每闭合一个提交单元就落一次提交的稳定频率。它与改动体量无关——一个提交单元可以是 1 行，也可以是 1 万行。
_Avoid_: 批量提交、定时提交、commit 频率

**功能完成信号**：
判定提交单元已经闭合的可观察事件。它是触发提交动作的唯一依据；没有信号就不提交。
_Avoid_: 完成感、任务结束、done、差不多了

**会话级授权**：
用户在会话开始时给出的、允许自动提交的显式许可。它只覆盖 commit、只覆盖当前工作目录所在的那一个仓库，且不跨会话继承。
_Avoid_: 默认同意、隐式授权、免确认模式、自动模式

**硬红线**：
即使已获会话级授权也拒绝自动执行的动作：把凭据推入仓库，以及一切破坏性 git 操作。
_Avoid_: 例外清单、风险提示、安全确认

**节奏层**：
commit-auto 在提交链路上的位置——只决定「何时提交」与「如何切分」，实际提交动作仍由审阅门执行。
_Avoid_: 包装层、外壳、执行器

**审阅门**：
另一技能 commit-report 提供的强制关卡：展示变更总揽与 commit 信息全文，用户明确确认后才执行提交。
_Avoid_: 确认弹窗、二次确认、checkpoint

**提交意图**：
commit-auto 交给审阅门的「这一笔提交单元是什么」的一句话说明，用于对齐文案语义。它不是最终 commit message——message 一律由审阅门按其既有规则生成。
_Avoid_: commit message、提交文案、主题行

**干跑**：
只输出「此刻会提交哪些文件、提交意图是什么」而不执行提交的报告形态。它是本技能唯一的验证手段。
_Avoid_: 预览、模拟提交、trial
