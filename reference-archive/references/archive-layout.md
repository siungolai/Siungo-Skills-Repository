# 归档骨架细则（archive-layout）

> `SKILL.md` §2 讲的是「为什么这样分层」，本文件讲「具体怎么排、怎么写、怎么命名」。

---

## 一、三层目录的职责边界

| 目录 | 装什么 | 能不能改内容 | 出处怎么记 |
|---|---|---|---|
| 归档根 | 编号 Markdown + `README.md` 索引 | 整理文档可改，原文存档不改 | 文件头部的「来源 / 采集时间」两行 |
| `assets/` | 本地化后的图片与图标 | 不改（改了就不是原件） | 文件名保留上游尾段，改写扩展名 |
| `downloads/` | 原样下载的 PDF、固件、压缩包、第三方源码包 | 不改 | 清单表里记 URL + sha256 + 字节数 |
| `reference-source/` | 上游仓库的逐字节镜像 | 绝对不改 | 记录上游仓库 URL、分支、commit、树快照文件数 |

**镜像目录的纪律**：里面是上游的代码，不是你的代码。哪怕上游有 bug 也照抄——你改了就失去对照价值，对账时会分不清是上游变了还是你改的。

## 二、Markdown 编号规则

- 编号从 `01` 起连续，**不留空洞**。中间删掉一个文件，就把后面的编号全部前移。
- 编号前缀 + 中文主题名，主题名是**内容**不是序号：`02-硬件速查表.md` 优于 `02-速查表2.md`。
- 第一个文件固定是 `README.md`（不占编号），它是索引。
- 原文存档与整理文档**混在同一编号序列里**，靠文件名区分：`01-产品总览.md`（原文存档）vs `02-硬件速查表.md`（整理文档）。

**为什么要连续**：离线归档的读者靠文件名排序来建立阅读顺序。编号有洞，读者会以为「这里缺了一页没给我」。

## 三、每份文档的头部格式

原文存档（官方页面的 Markdown 转写）：

```markdown
# <页面标题>

> 官方来源：<完整 URL>
> 采集时间：<YYYY-MM-DD> ｜ 采集方式：<转写方式>
> 本文件为原页面正文存档，内容未做增删改写；图片已下载到同目录 `assets/`。

<正文>
```

三行的标签（`官方来源` / `采集时间` / `采集方式`）与那句存档声明由脚本写入，标签本身可通过配置替换——**但一行都不能少**：少了来源 URL，这份存档就无法回溯到原文；少了采集时间，隔几个月再看就不知道它对应的是哪一版页面。

整理文档（派生结论）：

```markdown
# <标题>

> 本文由多路来源交叉核对得出，每条结论标注出处。
> 标记含义：【官方表】官方接口表图 / 【原理图】原理图网表 / 【BSP】上游驱动源码 / 【文档】官方文档正文。

<正文>
```

**出处标记要成体系**：同一份整理文档里，四种标记的含义必须固定不变，读者才能建立信任。

## 四、索引 README 的必备五块

1. **从哪里开始**——按用途而非按文件名给入口（"要烧固件看这篇，要查引脚看那篇"）；
2. **关键事实**——五到十条最常被查的结论，**每条带出处**；
3. **交叉验证说明**——几路来源对上了、哪路缺席、为什么；
4. **归档自检表**——链接、镜像完整性、固件校验、结论可回溯四项的最近一次结果与日期；
5. **原始来源**——全部官方 URL 清单，一行一个。

**为什么要第 4 块**：自检结果写进索引，等于让读者随时知道这份归档「上次验证是什么时候、验过什么」。缺了它，归档的可信度只存在于作者脑子里。

## 五、固件清单表

官方 Releases 的资产要**逐个**列，不只列常用的那几个：

| 固件 | 版本 | 来源 | 本地路径 | sha256 |
|---|---|---|---|---|

清单要标注每类固件的用途：

- **例程预编译固件**——上游为每个示例单独构建的产物，用户按例程选；
- **整机出厂固件**——刷进设备即用的完整镜像；
- **第三方适配固件**——上游仓库里没有、但官方文档推荐的社区适配版本。

## 六、镜像体积的取舍

上游仓库可能几百 MB，文档站可能有上百个外链。取舍原则：

| 内容 | 镜像？ | 理由 |
|---|---|---|
| 上游仓库源码 | 镜像 | 用户要基于它改代码；且是核对事实的权威来源 |
| Release 固件二进制 | 镜像 | 用户要直接刷；体积可控 |
| 数据手册 PDF | 镜像 | 离线查参数，且上游站点可能改版 |
| 文档站图片 | 镜像 | 正文引用，缺了文档就残缺 |
| 文档站全部历史页面 | 不镜像 | 只抓当前在导航里的页面 |
| 无关大文件（工具链、模型、第三方大库） | 不镜像 | 与归档目标无关，体积失控 |

**判断标准**：这份东西读者在离线查这份归档时**会用得上**吗？会用就镜像，不会就不镜像。
