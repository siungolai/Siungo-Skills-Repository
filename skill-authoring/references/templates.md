# 骨架与模板（templates）

> 复制粘贴用。`<…>` 是占位符，落地时必须替换，不能原样留在文件里。
> `CONTEXT.md` 与 ADR 的格式源头是上游技能 `domain-modeling`（`CONTEXT-FORMAT.md` / `ADR-FORMAT.md`）；本文件是它在**本仓库**的落地形态，两者冲突时以 `domain-modeling` 为准。

---

## 1. 骨架模板（`SKILL.md`）

````markdown
---
name: <技能名>
description: <职责一句话>：<触发情形 1>、<触发情形 2>…时使用。
agent_created: true
version: 1.0.0
last_updated: <YYYY-MM-DD>
author: siungolai
---

# <技能名>：<一句职责>

> ⚠️ **触发加载检查**：收到任何「<触发词 1> / <触发词 2> / <触发词 3>」类意图时，**先确认本技能已加载**——若本技能不在当前会话的可用技能列表里（技能快照可能早于本技能安装或更新），先用当前环境的技能加载机制加载它，然后按其流程执行。切忌在未加载技能的情况下直接<该技能最危险的动作>。

定位：<与谁分工、边界在哪>。<核心机制一句话>。版本历史见 [`references/version.md`](references/version.md)。

## 1. 何时使用          <!-- 条件性：只有 1 个触发分支时整章删除；存在时必须是第 1 章 -->

| 情形 | 动作 |
|---|---|
| <用户会怎么说> | 走 §<N> <哪条流程> |
| <不属于本技能的情形> | <该找谁> |

## 2. <流程第一阶段>

<每步给出判据与停止条件>

## …  <其余流程章节>

## N-1. 安全边界（硬性，任何路径下均适用）   <!-- 条件性：会执行不可逆动作时才写 -->

1. **<禁止的动作>**——<为什么>。

## N. 完成后报告

改动完成后一次性向用户报告：

1. <必须报告的第 1 项>
2. <必须报告的第 2 项>
````

**触发加载检查块的句式是固定的**，只有两处要换：`<触发词…>`（用用户真会说的话，不是技能名）与 `<该技能最危险的动作>`（如"直接动服务器""自行提交""动手写技能"）。

**注意**：块里不要写具体工具名（如 `skills_list` / `skill_view` / `execute_code`）——本仓库的技能是公开分发的，写死某一宿主工具名，换一个宿主就是死引用。

## 2. frontmatter 模板

```yaml
---
name: <技能名>
description: <职责一句话>：<触发情形 1>、<触发情形 2>…时使用。
agent_created: true
version: 1.0.0
last_updated: <YYYY-MM-DD>
author: siungolai
license: MIT                              # 可选，只在需要时加
platforms: [windows, linux, macos]        # 可选，只在技能真的挑平台时加
metadata:                                 # 可选，宿主专属元数据
  <宿主>:
    tags: [<标签>]
    related_skills: [<技能名>]
---
```

六键顺序固定（M3）；可选扩展只能排在后面。

## 3. `references/version.md` 模板

```markdown
# <技能名> 修订记录

> 按时间倒序。每条对应 `SKILL.md` frontmatter 里的 `version` 与 `last_updated`。

| 版本 | 日期 | 变更 |
|---|---|---|
| 1.0.0 | <YYYY-MM-DD> | 首次创建：<一句话说明这个技能做什么>。 |
```

**历史条目不改写**（M7 例外）：旧条目里出现的旧章节号、旧版本号、已删除的文件名一律保留原样。

## 4. `CONTEXT.md` 模板

```markdown
# <技能名>（<中文名>）

<一两句：这个技能在什么语境下工作。>

## Language

**<术语>**：
<释义：它是什么、边界在哪、和相近概念怎么区分。>
_Avoid_: <同义词 1>、<同义词 2>、<英文词>

**<术语>**：
<释义。>
_Avoid_: <同义词>
```

规则：只定义**项目特有**的语言，通用词不收；每条必须有 `_Avoid_`（同义词是歧义的来源）；只写语言，不写实现（P5）。

## 5. `docs/adr/NNNN-<中文标题>.md` 模板

```markdown
# <短标题：一句话说清决策是什么>

<第 1 段：背景与问题——是什么逼出了这个决策。>

<第 2 段：决策内容，以及接缝处的细节——边界划在哪里、谁负责什么。>

<第 3 段：替代方案，以及否决它的理由。>
```

规则：编号连续、四位补零；**三条判据同时成立才写**（难以反转 / 没有上下文会令人惊讶 / 是真实权衡的结果）；不写 Status、Considered Options、Consequences 这类小标题（本仓库的 ADR 是 3–4 段纯散文）。

## 6. README 片段模板

技能表一行（列顺序：技能 / 版本 / 简介 / 结构）：

```markdown
| [`<技能名>`](./<技能名>/) | <版本> | <简介：流程用 → 串起来，一句说清管什么、内置哪些门槛> | SKILL.md + references/ |
```

「目录结构」块里的一段：

```
├── <技能名>/
│   ├── SKILL.md                      # 技能主文件：<一句话>
│   └── references/
│       ├── <文件>.md                 # <一句话>
│       └── version.md                # 修订记录（版本历史，按时间倒序）
```

四处必须同步：技能表行、目录结构块、徽章 `skills-N` 的数字、以及各自的版本号（D4、D5）。
