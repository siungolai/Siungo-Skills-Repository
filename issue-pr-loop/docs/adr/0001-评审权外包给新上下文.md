# 评审权外包给独立新上下文，而不是执行线自查

这套流水线把评审结论的产出交给一个**与执行线无关的新上下文**，并把「结论 / 复核动作 / 证据」三段缺一视为未评审。

把评审留在执行线上的方案被否决，理由是自评天然带叙事：提交者已经知道自己改了什么、为什么这么改，他会把「我已经测过」当成证据，而独立评审人要的是「我自己跑出来的原始输出」。两者的差别在出问题时才暴露——自查过的 PR 出问题时，复盘只能得到「当时觉得没问题」。把评审放到新上下文后，叙事被切断，评审人只能读 PR 与代码，因此必须自己跑门禁；这同时把主控会话从「等评审」里解放出来，并行队列才不会因为一个等待点停住。

代价是评审人可能因为缺少上下文而问出已经答过的问题。缓解方式不是把上下文塞给它，而是把上下文写进单子与 PR 正文——派发物料只给编号、分支、改动文件与门禁清单，不给 PR 正文，评审人自己去读。另一个被否决的方案是「同会话换个人格再评一遍」：人格不隔离记忆，产出仍然是自查。
