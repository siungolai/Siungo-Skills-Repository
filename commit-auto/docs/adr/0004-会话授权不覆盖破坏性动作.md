# 会话级授权不覆盖破坏性动作

会话级授权的语义是「你是否需要被打断」，不是「是否允许我把密钥推上 GitHub」。因此有两条**硬红线**，即使已授权也拒绝自动执行：其一，凭据零入库——`.env`、`*.key`、含 token 的文件、超大文件一旦进入提交范围即中止并报告；其二，破坏性 git 操作——`git init`、删除文件、`--no-verify`、force push、amend 已推送提交一律不做。

替代方案是把这两类动作也纳入「例外清单」，即授权后仍逐次询问。被否决的理由：确认门和拒绝执行是两种不同的安全姿态，把不可逆泄露风险降级成一个可以被点掉的弹窗，等于没有边界。这两条与 `deploy-report` 已有的「凭据零入库硬性边界」保持同一姿态。
