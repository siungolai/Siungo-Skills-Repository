# esp32-firmware-bringup（ESP32 固件 bringup）

> 用于把「规格书上的 ESP32 硬件参数」变成「本机实测事实」，并把新器件从接线推进到长跑的技能语境。本文件只定义语言；实现、流程与参数在 `SKILL.md` 与 `references/`。

## Language

**bringup**：
让一条从未验证过的硬件链路在本机跑通的最小验证过程，产出的是「可依赖的地基」而不是功能。判据是客观的（地址应答、单路不互扰、拔外设节拍不漂移），不是「看起来对了」。
_Avoid_: 调试、联调、点亮、试机

**拓扑**：
器件之间怎么接：谁挂在哪条总线哪个通道、地址是什么、上拉在哪一侧、电平是多少。拓扑假设的错误影响的是整个上层架构，不是局部改动——这是 bringup 必须先于上层代码的理由。
_Avoid_: 接线图、电路、连接关系

**节拍（tick）**：
固件自己的计时脉搏，由 `millis()` 驱动，与外设是否在线无关。它是长跑稳定性的度量对象：实测多少次每秒、漂移多少。
_Avoid_: 定时、周期、心跳、刷新率

**从机（slave device）**：
总线上被主控访问的器件（屏、传感器、多路复用器）。它「在线」指能被探测到；不在线时刷新必须整体跳过，而不是阻塞在超时上。
_Avoid_: 外设、模块、从设备、传感器（泛指时）

**物理层**：
电源、通断、静态电平、焊接这一层。诊断阶梯里它排在固件之前；通断没过的链路，地址扫描与日志全是无效劳动。
_Avoid_: 硬件层、电路层、板级

**判读**：
从一次观测得出结论的那一步。判读会骗人：「背光亮」不等于「供电到位」，「上拉读到 HIGH」不等于「信号接到了器件」——结论要能经得起拔掉/替换这类反证。
_Avoid_: 分析、判断、读数

**离线保护**：
从机不在线时刷新函数直接返回、不发任何总线事务的机制。它让计时精度与从机在线状态解耦。
_Avoid_: 容错、异常处理、重试

**上拉并联**：
多路各自带上拉的总线被同时连通时，等效上拉阻值下降、低电平驱动余量变小。量化到逼近从机 sink 极限时，一次只选通一路是设计约束而非优化。
_Avoid_: 上拉冲突、电阻叠加

**自校准判决**：
用同一环境实测的两个量相互比较来做位判决（如 `highCycles > lowCycles`），循环开销在两个量上同时放大、比较时抵消；而不是拿名义时长当绝对阈值。
_Avoid_: 动态阈值、自适应阈值

**待 bringup 验证**：
规格书已核实、但本机还没实测的状态标记。写在 `HARDWARE.md` 里，提醒读者这不是可依赖的地基。
_Avoid_: 未测试、待确认、TODO

**事实三态**：
器件状态的三种标注——实测可用 / 规格已核实 / 未调通或已废止。三者不可混写：把规格书参数写成实测会让读者误以为验证过。
_Avoid_: 已验证、可用性、状态

**台架压缩**：
用 `TIME_SCALE` 把长周期按比例缩短，在台架上快速验完多种周期；验完必须复位为 1，否则带着压缩比例进长跑。
_Avoid_: 加速测试、倍速、快进
